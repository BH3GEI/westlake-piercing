Shorty mapping (ART collapses every reference — object OR array — to 'L'):
  nDrawBitmap(JJFFJIII)V     -> shorty "VJJFFJIII"      (no reference args; all primitives)
  nDrawTextRun(J[CIIIIFFZJJ)V-> shorty "VJLIIIIFFZJJ"   (the [C char[] becomes L)
Arg-slot indexing (confirmed vs drawRoundRect VJFFFFFFJ @2146 and drawPath VJJJ @2464): long/double = 2 vreg slots,
float/int/boolean = 1 slot, object/array reference = 1 slot. Marshal a reference with the rail's existing idiom
soa.AddLocalReference<jXxx>(ObjArg(args[N])) (see the array args at interpreter.cc:1210-1212). @FastNative statics
here use the NORMAL JNIEnv*/jclass ABI via GetEntryPointFromJni(), exactly like the drawRoundRect/drawPath arms.

    } else if (shorty == "VJJFFJIII" &&
               (method->GetDeclaringClass()->DescriptorEquals("Landroid/graphics/BaseRecordingCanvas;") ||
                method->GetDeclaringClass()->DescriptorEquals("Landroid/graphics/BaseCanvas;"))) {
      // [DAYU600][drawop] BaseRecordingCanvas/BaseCanvas.nDrawBitmap(long canvas, long bitmapHandle, float left,
      //   float top, long paintOrZero, int canvasDensity, int screenDensity, int bitmapDensity) — VJJFFJIII
      //   (@FastNative). The left/top BitmapDrawable path = ImageView icons / raster PNGs. Regular-static rail,
      //   NORMAL ABI via GetEntryPointFromJni() like nDrawRoundRect. Class-guarded so a bare shorty can't hijack an
      //   unrelated static native whose entry may be a dlsym stub. End-to-end also needs a valid bitmap handle
      //   (nativeCreate/decode) live on device — board-verify.
      using fntype = void(JNIEnv*, jclass, jlong, jlong, jfloat, jfloat, jlong, jint, jint, jint);
      fntype* const fn = reinterpret_cast<fntype*>(method->GetEntryPointFromJni());
      ScopedLocalRef<jclass> klass(soa.Env(),
                                   soa.AddLocalReference<jclass>(method->GetDeclaringClass()));
      fn(soa.Env(), klass.get(),
         *reinterpret_cast<jlong*>(&args[0]),    // canvas       (slots 0,1)
         *reinterpret_cast<jlong*>(&args[2]),    // bitmapHandle (slots 2,3)
         *reinterpret_cast<jfloat*>(&args[4]),   // left         (slot 4)
         *reinterpret_cast<jfloat*>(&args[5]),   // top          (slot 5)
         *reinterpret_cast<jlong*>(&args[6]),    // paintOrZero  (slots 6,7)
         static_cast<jint>(args[8]),             // canvasDensity
         static_cast<jint>(args[9]),             // screenDensity
         static_cast<jint>(args[10]));           // bitmapDensity

CROSS-CHECKS DONE
-----------------
- AOSP-11 BaseCanvas.java signatures match the smali arg order exactly (start/count/contextStart/contextCount for
  text; canvasDensity/screenDensity/bitmapDensity for bitmap).
- Slot arithmetic re-derived independently for both (drawBitmap: 2+2+1+1+2+1+1+1 = 11 slots; drawText: 2+1+1+1+1+1+
  1+1+1+2+2 = 14 slots) and matches the args[] indices above.
- ObjArg(args[N]) is the same helper the rail uses for array/object args (interpreter.cc:1171,1187,1210-1212); soa is
  in scope in this rail (drawPath/drawRoundRect arms use it).

shaping for drawText are the two things a source review can't fully prove — both are board-observable only.
