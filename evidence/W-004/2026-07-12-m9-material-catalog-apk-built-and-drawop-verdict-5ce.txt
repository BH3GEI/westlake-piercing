RESULT 2 — substrate draw-op verdict: the catalog launch frame HOLDS but is EFFECTIVELY BLANK
--------------------------------------------------------------------------------------------
Source-level analysis of the catalog's launch screen (io.material.catalog @ ac7e18e) against the
5ce substrate's documented Canvas-op binding (substrate-canvas-op-shorty-map memory: PAINTS =
drawRect/drawOval/drawRoundRect/drawLine/drawPaint/drawColor; SILENT NO-OP = drawCircle/drawArc/
drawPath/drawVertices/drawBitmap/drawText; shader-on-a-*working*-op = SIGSEGV).

Launch path (file:line evidence):
  - Launcher = MainActivity (catalog/.../AndroidManifest.xml MAIN/LAUNCHER), setContentView
    R.layout.cat_main_activity = a bare FrameLayout container (MainActivity.java:55).
  - First fragment = TocFragment (table-of-contents grid), DaggerFragment (TocFragment.java:59).
    On a clean install getDefaultDemoLanding()="" (FeatureDemoUtils.java:112-115) => NO auto-jump
    into a demo; the TOC grid IS the first screen.
  - Theme.Catalog -> Theme.Material3Expressive.DayNight.NoActionBar; windowBackground = solid
    ?attr/colorSurface (no gradient/bitmap window bg).
  - TOC grid cells = R.layout.cat_toc_item = plain FrameLayout (NOT MaterialCardView — CORRECTION
    to an earlier assumption; there are no rounded-rect cards, no card elevation in the launch
    frame), each with an ImageView icon (raster PNG), a TextView title, and a
    selectableItemBackground ripple foreground (drawn only on touch).

What the FIRST FRAME actually does on this substrate:
  RENDERS (supported ops):
    - full-screen colorSurface background fill (ColorDrawable -> drawRect/drawColor)
    - cat_toc_grid_top_divider bar (ColorDrawable -> drawRect)
    - GridDividerDecoration separator lines between cells (plain Paint, no shader -> drawLine)
    - (STATUS_WIP cells only) a rotated solid-color WIP banner rect (drawRect under a matrix)
  SILENTLY DISAPPEARS (NO-OP, no crash):
    - ALL text: logo title, every cell title, WIP text (drawText/drawTextRun)
    - ALL grid icons (raster PNG BitmapDrawable -> drawBitmap)
    - toolbar search/settings icons + logo mark (VectorDrawable -> drawPath)
    - AppBar/Toolbar surface tint (Material3 MaterialShapeDrawable -> drawPath)
    - elevation shadows (RenderThread outline shadow, not an app Canvas op)
  HARD-CRASH (SIGSEGV): NONE at first draw. No shader is bound to a working op in the idle launch
    frame — every shader-capable surface routes through drawPath/drawBitmap, which are NO-OPs, so a
    shader there is silently dropped, not executed. The only residual crash risk is the
    touch-triggered ripple, and only IF this runtime's RippleDrawable takes the BitmapShader-mask ->
    drawRect path; with the default rectangular selectableItemBackground mask it stays on the
    drawCircle NO-OP path and also does not crash. => interaction-triggered, not first-frame.

VERDICT: On the 5ce imageless substrate the Material Catalog launch frame REACHES A STABLE, HELD
FRAME (it does NOT SIGSEGV before presenting — correcting the earlier "drawPath/shader SIGBUS is
the wall" framing, which was about codex's more-advanced gouraud triangle iteration, not the
catalog). BUT the held frame is effectively EMPTY: a colored rectangle crossed by faint grid
divider lines, with NO component labels, NO icons, NO logo, NO toolbar chrome. The blocking
substrate limitation for THIS app is not a crash — it is that drawText, drawBitmap, and drawPath
(VectorDrawable + MaterialShapeDrawable) are all no-ops, so every semantically meaningful pixel is
invisible.
