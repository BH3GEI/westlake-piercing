CONCURRENCY -> REBOOT INCIDENT (single-writer rule vindicated) + cleanup
-----------------------------------------------------------------------
codex's triangle run (08:56:22) and my colorApk run (08:56:24) hit the board within 2s of each
other while the load average was already ~13. Shortly after both completed, the board dropped
off hdc and REBOOTED (uptime 51min -> 1min; confirmed by the post-boot "USB 连接方式" dialog).
I did NOT reboot it (my run had already exited clean and the board answered a ps query after);
most likely a watchdog/OOM from the accumulated concurrent bring-up load. This is exactly the
failure the DISPATCH single-writer rule prevents: two writers on one board's shared
/data/local/tmp scratch + single display + heavy VM/dex2oat load. Lesson: do NOT run a
concurrent board bring-up (even a fully isolated one) while codex is live on 5ce — they resume
every few minutes.
