[1] WestlakeUpscreen.java 不能走探针的 shim classpath 编译(会 compile-fail)
================================================================
现象(observed):
- WestlakeUpscreen.java 直接用 android.view.View 的 measure/layout/draw、
  View.MeasureSpec.EXACTLY、MotionEvent.dispatchTouchEvent 等真方法。
- 探针 build (test-fixtures/dayu600-apk-probe/build-probe-mac.sh) 的 javac
  classpath = `framework-shim:android.jar`(shim 在前)。
- framework-shim 里有 android/view/View.class + View$MeasureSpec.class 的
  **部分桩**,会 shadow 掉 android.jar 里的真 View。
  验证: `grep -cE 'public.*(measure|layout|draw|dispatchTouchEvent)'`
  test-fixtures/dayu600-framework-shim/src/android/view/View.java = **0**
  → shim View 一个都没有这些方法。
- 因此若照 handoff §6 旧写法"把 WestlakeUpscreen.java 加进 build-probe-mac.sh
  的 javac 源集",会报 `cannot find symbol: measure/layout/draw/MeasureSpec.EXACTLY`。
- 对照(observed): 同一份 WestlakeUpscreen.java 用**纯 android.jar**(不含 shim)
  能编过。矛盾点纯粹是 shim 的 shadow。

修法(inferred,已有现成产物,免重编):
- **别重编**。直接合并现成 dex:
  scratchpad-shared/upscreen-render/upscreen-render.dex.jar
  内含 classes.dex,**dex version = 035**(与探针 dex 同代,板可收)。
  用 d8 把它并进探针 dex,或作为第二 dex 一起 load。
- 若确要从源重编: 单独用**纯 android.jar**(不带 shim)编 WestlakeUpscreen.java →
  得 .class → d8 → 再和探针 dex 合并。现成 .class 也在:
  scratchpad-shared/upscreen-render/WestlakeUpscreen.class(6014 B)。

[3] WestlakeUpscreen 现成 API 与 handoff 调用点核对(javap 实测)
================================================================
FQN(observed): **adapter.window.WestlakeUpscreen**(不是裸 WestlakeUpscreen)。
探针/handoff 引用要用全限定名。
公开方法(与 handoff §6 调用点比对):
- `public static int show(View, int, int)`          ✓ 匹配 handoff `show(view,w,h)`
- `public static void drawFrame(View)`               ← **变色循环要用这个**
- `public static void pushFrame()`                   ← 只重推旧帧,**不能用来变色**
- `public static View pureColorView(Context, int)`   ← **陷阱,别用**(见下)

================================================================
[4] 变色循环必须用 drawFrame(view),不是 pushFrame() —— 否则违反"变色"验收线
================================================================
现象(observed,读 WestlakeUpscreen.java:88-124):
- `show(v,w,h)`:`record(v,w,h)` 把传入 View 录成 display list(sRoot)→ nativeInit → nativeDrawFrame。
- `pushFrame()`:只 `if(sRoot!=null) nativeDrawFrame();` —— **不重录**,重推的是**旧** display list。
- `drawFrame(v)`:`record(v,sW,sH); nativeDrawFrame();` —— **重录**,重跑 ColorView.onDraw→drawColor(新 mColor)。
影响:
- handoff §6 原写 `view.nextColor(); pushFrame();`:nextColor 改了 mColor+invalidate,但 pushFrame 推旧帧
  → **屏上颜色不变** → 违反用户"变色是硬要求"。
- 已修 handoff §6 step 1 为 `view.nextColor(); adapter.window.WestlakeUpscreen.drawFrame(view);`。

陷阱: **别用 WestlakeUpscreen.pureColorView(ctx,color)** —— 那是 adapter 自造纯色 View,
像素不来自 APK 的 Canvas.drawColor,不满足"APK 自绘"验收线。只喂 APK 的 ColorView 实例。
