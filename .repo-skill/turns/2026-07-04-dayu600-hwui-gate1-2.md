## Agent Action

**Gate 1 — built `libhwui.so` from AOSP 15 for aarch64-linux-ohos.** Compiled all
171 hwui sources against the OHOS 6.0 SDK clang + the board's own m133 Skia
(`libskia_canvaskit.z.so`), with a header-only minikin stub and AOSP-15 libutils
real sources. Scripts: `ports/dayu600/scripts/build-libhwui-smoke-macos.sh`,
`build-support-objs.sh`, `link-libhwui-macos.sh`. Default visibility so the
`register_android_graphics_*` symbols export.

**Gate 2 — hwui's own pipeline renders on the panel** (green bg + red rect,
snapshot-verified). Native harness `ports/dayu600/gfx-smoke/` drives
RenderProxy → RenderThread → CanvasContext → SkiaOpenGLPipeline into a
display-attached RSSurfaceNode's OHNativeWindow. Five walls fixed: fake
`libandroid.so` (ASurfaceControl dlsym), `Properties::isolatedProcess` (no
AChoreographer), `oh_anw_wrap` ANativeWindow ABI shim (query@offset 88), EGL
interposer (unwrap before device libEGL), and the deep one — the OHOS-Skia
`GrDrawingManager::flush` gate skipping GPU submit when `AtlasPathRenderer::preFlush`
fails; root cause an `-DGPU_TEST_UTILS` `GrContextOptions` ABI mismatch, fixed by
interposing `GrDirectContexts::MakeGL` and setting `fGpuPathRenderers = kNone`.

**Gate 3 — diagnosed, not fixed.** Bisected on-device: baseline and
real-`framework.real-sdk.jar`-on-BCP both launch 2048 (`game0` focused);
adding the hwui-enabled `liboh_android_runtime.so` makes
`register_android_graphics_classes` block in the appspawn-x embedded-ART child →
OHOS AMS `LIFECYCLE_TIMEOUT` (`MainActivity load timeout`) kills it. Earlier
"samgr `Parcel::InjectOffsets` crash" was a stale-faultlog red herring. Next: find
and defer/stub the blocking synchronous OHOS call inside a graphics registrar.
